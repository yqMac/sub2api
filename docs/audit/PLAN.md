## 一、背景与目标

### 业务需求

1. **审计**：记录每个 API 请求/响应的完整内容，按多维度（用户、部门、内容类型、模型、时间）查询和统计
2. **组织架构**：基于飞书的部门/租户层级，支持部门级统计和管理
3. **告警**：基于审计数据触发告警（敏感内容、异常频次、违规请求、配额超限）
4. **拦截**：在请求路径上根据规则阻断/降级（关键词过滤、用户/部门白名单、模型黑名单）

### 设计原则

| 原则 | 含义 |
|------|------|
| 复用现有基础设施 | 不重建告警引擎、限流、异步写入框架 |
| 数据模型先行 | P0 必须把表结构和扩展点定下来，避免返工 |
| 性能零损耗（关闭时） | 功能关闭时 == 现有性能，不影响生产 |
| 配置驱动 | 截断大小、保留天数、上游捕获等运行时可调 |
| 异步优先 | 所有审计/统计/告警写入异步执行，不阻塞响应 |
| 标记法识别 | 所有二开代码加 `[bmai-fork]` 标记 |

## 三、核心数据模型

详见 [DESIGN-BACKEND.md § 数据模型](./DESIGN-BACKEND.md#数据模型)。

四张核心表：
1. **organizations** + **departments** + **user_departments** — 组织架构
2. **audit_logs** — 审计日志主表（按月分区，含部门冗余字段、风险标记）
3. **audit_stats** — 多粒度多维度预聚合表
4. **audit_rules** + **audit_rule_events** — 拦截/告警规则与命中事件

## 四、请求路径上的三个 Hook 点

```
请求进入
   │
   ├─ [Pre-Audit Hook]  ← 拦截规则评估（rule_type=pre_block）
   │   - 关键词、频次、大小、模型黑名单
   │   - 命中 block 动作 → 返回 403 + 写 audit_log(intercepted=true)
   │   - 命中 warn 动作 → 加 risk_tag 继续
   ↓
   现有路径：认证 → 并发 → 账号选择 → Forward
   ↓
   ├─ [审计写入]  ← 异步写入 audit_logs（含部门冗余）
   │
   └─ [Post-Audit Hook]  ← 异步评估（rule_type=post_alert/post_tag）
       - 响应内容关键词、敏感数据泄露
       - 命中 alert → 复用 OpsAlertEvent 系统发邮件
       - 命中 tag → 更新 audit_log.risk_tags
```

## 六、性能影响评估

| 场景 | 开销 |
|------|------|
| 全部关闭 | 零（一个 bool 检查） |
| 仅审计开启 | < 0.1ms（异步写入） |
| Pre-Audit 规则启用（5 条） | < 1ms（内存中规则匹配，规则缓存） |
| Post-Audit 规则启用 | 0ms（异步评估） |
| 统计查询（部门维度，30 天） | < 50ms（走预聚合表） |
| 部门同步（飞书 API） | 异步，不阻塞登录 |

关键优化：
- 拦截规则缓存在内存中（启动时加载 + 变更时刷新），不查 DB
- 预聚合表覆盖多种粒度，查询不走主表
- 部门信息冗余写入 audit_logs，避免 JOIN

## 七、存储控制

- 默认 preview 上限 32KB/字段，4 个字段最大 128KB/行
- audit_logs 按月分区，`DROP PARTITION` 清理历史
- 默认保留 30 天，可配置
- 上游请求/响应捕获默认关闭，按需开启
- audit_stats 预聚合表独立保留（保留更久），不受主表清理影响

## 八、实施优先级

### P0：核心审计 + 组织架构（4-6 天）
- 后端：建表（organizations/departments/audit_logs/audit_rules）
- 后端：审计写入（pre-hook 占位，post-hook 占位，规则引擎暂存）
- 后端：列表/详情/设置 API
- 后端：飞书 OAuth 同步部门信息（异步可降级）
- 前端：审计日志列表 + 详情弹窗 + 设置页
- 前端：组织架构管理页（基础 CRUD）

### P1：统计 + 多维度（3-5 天）
- 后端：预聚合任务、统计 API（多维度）
- 前端：统计概览页（部门钻取、用户/模型维度）

### P2：规则引擎（3-5 天）
- 后端：规则引擎、Pre/Post Hook 实现
- 后端：扩展 ops_alert 引擎注入 audit metrics
- 前端：规则管理页 + 规则编辑器

### P3：增强（2-3 天）
- 部门级配额、部门级速率限制
- 内容类型响应时修正
- 导出功能（CSV/Excel）

## 九、风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| 存储增长过快 | 磁盘占满 | 分区表、自动清理、可配置保留 |
| 性能回退 | 响应延迟 | 关闭开关、零开销路径 |
| 规则误拦截 | 业务受阻 | warn 模式优先、灰度上线 |
| 飞书 API 限流 | 部门同步失败 | 异步、降级、手动触发 |
| 上游响应包含敏感数据 | 误存敏感信息 | 上游捕获默认关闭、字段级开关 |
